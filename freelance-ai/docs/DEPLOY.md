# نشر مُستقبِل لعميل (خطوة بخطوة)

> لا أنشر ولا أنفق ولا أربط حسابات العميل بدون موافقتك. هذا دليل لتنفذه أنت (أو أنفذه بعد موافقتك).

## 1) الأسرار (متغيرات بيئة — لا تُرفع إلى Git)
| المتغير | الاستخدام |
|---|---|
| `ANTHROPIC_API_KEY` | مفتاح Claude (ضع **حد إنفاق شهري** في لوحة Anthropic) |
| `CLIENT_CONFIG` | مسار `clients/<client>/config.json` |
| `ADMIN_TOKEN` | نص عشوائي طويل لقراءة `/api/admin/state` |
| `DAILY_CAP` / `RATE_PER_MIN` | سقف الرسائل اليومي/لكل زائر (يحمي ميزانيتك) — الافتراضي 500 / 15 |
| `LOG_FILE` | مسار سجل JSONL (للتقرير الشهري). فعّله فقط بموافقة العميل؛ يُحذف بعد المدة المتفق عليها |
| `TRUST_PROXY=1` | إذا كان خلف وسيط (Render/Fly) ليقرأ IP الزائر الحقيقي |
| `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID`, `WHATSAPP_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN` | قناة WhatsApp (من حساب Meta **الخاص بالعميل**) |
| `STAFF_WHATSAPP` | رقم الموظف لإشعارات التحويل والحجز الجديد (انظر القيد أدناه) |
| `BOOKINGS_FILE` | **مطلوب لأي عميل حقيقي**: ملف JSON دائم للحجوزات (حفظ ذري + fsync، صلاحية 0600). بدونه تضيع الحجوزات عند إعادة التشغيل |
| `CALENDAR_TOKEN` | سر طويل عشوائي لرابط `/calendar.ics?token=…` (اشتراك التقويم) |
| `REMINDER_TEMPLATE`, `REMINDER_LANG`, `REMINDER_HOURS` | تذكيرات WhatsApp: اسم قالب Meta المعتمد، لغته (افتراضي ar)، كم ساعة قبل الموعد (افتراضي 24). تتطلب `BOOKINGS_FILE` |
| `API_TIMEOUT_MS` | مهلة نداء Claude (افتراضي 25000) |

## 2) التشغيل
```
cd freelance-ai/demo/receptionist
npm test
CLIENT_CONFIG=../../clients/<client>/config.json ANTHROPIC_API_KEY=... PORT=3000 npm start
```
أي استضافة تشغّل Node 18+ تكفي (VPS صغير أو منصة PaaS). نسخة واحدة لكل عميل. الحجوزات تُحفظ على القرص عند ضبط `BOOKINGS_FILE` (احفظ نسخة احتياطية منه؛ إن فشلت الكتابة يُبلَّغ العميل بتحويل لموظف ولا يُعلَن حجز وهمي). `retention_days` في ملف العميل (افتراضي 90) يحذف تلقائيًا الحجوزات والتحويلات الأقدم. أضف `default_country_code` (مثل `"218"`) ليتعرف النظام على أرقام الهاتف بصيغها المختلفة.

## 3) ربط WhatsApp (Meta Cloud API) — يحتاج حساب العميل
1. العميل يملك Meta Business Account ويضيف رقمًا (لا يكون مسجلًا على تطبيق WhatsApp عادي).
2. في Meta for Developers: تطبيق ← WhatsApp ← خذ Phone number ID والـ Access Token (يفضل Token دائم من System User).
3. Webhook: URL = `https://<domain>/webhook`، Verify token = قيمة `WHATSAPP_VERIFY_TOKEN`، اشترك في `messages`.
4. `WHATSAPP_APP_SECRET` من إعدادات التطبيق — بدونه يرفض الخادم كل الرسائل (حماية من الطلبات المزيفة).
5. اختبر برقم تجريبي قبل الرقم الحقيقي.

**قيود يجب أن يعرفها العميل:**
- الرد على عميل ممكن خلال 24 ساعة من رسالته؛ بعد ذلك تحتاج قوالب رسائل معتمدة (تذكيرات المواعيد تدخل هنا) ورسوم Meta على العميل.
- إشعار الموظف عبر WhatsApp يصل فقط إذا راسل الموظف رقم النشاط خلال 24 ساعة؛ البديل الأضمن بريد/Telegram (يُضاف حسب الطلب).
- يدعم النص فقط حاليًا (الصور والصوت ترد عليها رسالة اعتذار).

## 5) التقويم والتذكيرات والإشعارات — ما يعمل وما لا يعمل
- **اشتراك التقويم:** أضف الرابط `https://<domain>/calendar.ics?token=<CALENDAR_TOKEN>` في Google/Apple/Outlook كـ"تقويم من رابط". هذه الخدمات تحدّث الاشتراكات **كل عدة ساعات** (ليس فوريًا) — لذلك يصل الموظف تنبيه حجز جديد أيضًا (حين يُضبط `STAFF_WHATSAPP`). الرابط سر: من يملكه يرى أسماء وأرقام العملاء؛ بدّله إن تسرّب.
- **إلغاء حجز بالخطأ:** `POST /api/admin/cancel` برأس `x-admin-token` وجسم `{"id":"<رقم الحجز>"}` (الأرقام في `/api/admin/state`).
- **التذكيرات:** تُرسل فقط لمن حجز عبر WhatsApp (هو موافقته)، بقالب معتمد من Meta بأربعة متغيرات بالترتيب: `{{1}}` الاسم، `{{2}}` الخدمة، `{{3}}` التاريخ، `{{4}}` الوقت. الموافقة على القالب وتكلفة الرسائل على حساب العميل.
- **إشعار الموظف** عبر WhatsApp يصل فقط إن راسل الموظف رقم النشاط خلال 24 ساعة؛ وإلا اعتمد على التقويم و`/api/admin/state`. (البريد غير مبني.)
- **الإلغاء وتغيير الموعد** يُحوَّلان لموظف ولا يُنفَّذان آليًا.
