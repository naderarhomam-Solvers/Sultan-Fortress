# skill-intake

ردّ بالعربي وباختصار. الأرقام والأكواد بالإنجليزي.

## الترتيب (دايماً، لكل رابط)

1. **اقرأ:** `add_repo` ثم clone سطحي (`GIT_LFS_SKIP_SMUDGE=1 git clone --depth 1`) خارج المشروع. اقرأ README وكل SKILL.md. لا تنفّذ أي سكربت منه.
2. **افحص:** الاتصالات الخارجية (روابط)، `eval`/`exec`/`subprocess`/`socket`/`base64`، طلب مفاتيح أو بيانات شخصية، الرخصة. إذا فيه شي مشبوه قل هذا قبل كل شي.
3. **اكتب التقييم:** وش هو، وش يسوي، نتيجة الفحص، والحدود (مثلاً مصادر أمريكية فقط).
4. **اكتب البرومت المحسّن** كبلوك قصير، وبعده شرح "ليش" لكل تعديل. التعديلات المعتادة:
   - نسخة محلية في `.claude/skills/` مع `SOURCE.md` (الريبو + رقم الكوميت + الرخصة).
   - ردود بالعربي، ووصف واضح لحدود التغطية بدون اختراع بيانات.
   - لا مفاتيح ولا إيميل ولا بيانات شخصية في ملفات المشروع، و`.gitignore` للمجلدات الشخصية.
   - الأوامر الخطرة (تنفيذ أوامر، إرسال، شراء) تحتاج موافقة صريحة ولا تشتغل في الخلفية.
5. **استنى الموافقة.** لا تضيف شي قبلها.
6. **أضف:** انسخ إلى `.claude/skills/`، سكيل منسّق إذا المجموعة كبيرة، commit ورفع على الفرع المحدد للجلسة. لا PR إلا إذا طلب.

## حدود

- لا تشغّل كود من ريبو خارجي. إذا تحتاج تشغّله (اختبارات مثلاً) قل للمستخدم ليش واستنى قراره.
- لا تعدّل كود السكيل الأصلي إلا بطلب. الإضافات في ملفات جديدة بجانبه.
- المستخدم يكتب بلهجة عامية، فإذا الطلب غير واضح اسأل سؤال واحد قصير بدل ما تخمّن.
